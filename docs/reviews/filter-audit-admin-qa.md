# Admin and QA list audit — 29 October 2026

Scope: the QA workspace and administration routes listed below. View controls operate on the full permission-scoped source, except delivery history, whose query is applied by the server before pagination. No application data, saved form order, review snapshots, permissions or import application rules were changed during this audit.

## Shared behaviour

- `services/listQuery.ts` supplies accent-insensitive, multi-term search, natural text/numeric comparison, stable ties and null-last ordering. Each search term may match a different meaningful field.
- `components/AdminListSort.tsx` provides a labelled, native select. Sort values are view state; changing them makes no API write.
- Facets are built from the entire permitted source before other filters, including archived/inactive values returned by that source. Eligibility pickers retain their existing active-only or role rules; these are not reporting exclusions.
- Dates sort as timestamps; counts sort numerically. Empty and invalid dates sort last in either direction. Each sortable list has a deterministic identity or business tie-break.
- Filters do not clear hidden selections or unsaved drafts. Managed-list editors remain mounted, and edited choices remain visible. Manual move buttons require the complete unfiltered configured-order view, and move handlers enforce the same condition.
