# Dashboard submitters and ELI submission roster

The process-records API adds nullable `submitterDisplayName`. Learning Walk, ALS Learning Walk, Work Scrutiny, Environment and CPD resolve it from the latest active submitted form's `submitted_by_user_account_id`. ELI resolves the latest explicit `elevate_practice.submitted` audit actor while the assessment remains submitted. Coaching uses its recorded completed-save actor; LIV uses the latest completed-cycle event actor; probation uses the latest observation-completion actor. The dashboard's row remains a case for the latter workflows. No subject, owner, reviewer, creator or later administrator is substituted when the recorded submitting/completing actor is missing. Existing reporting exclusions and access predicates are preserved.

`GET /api/v1/reports/eli-submissions?academicYear=...` returns one eligible staff member per row with staff and organisation identifiers, `hasSubmitted`, and optional submission timestamp/assessment record ID. The row identifies the assessment's staff member, including when someone else entered it on their behalf. The endpoint requires all/scoped report access. Its data query shares the exact eligibility CTE with staff participation, including archive/account/employment dates, academic year, organisation visibility and staff scope. ELI process-specific faculty visibility is applied to both. Only current submitted, unarchived assessments produce metadata; missing or reopened/draft assessments do not expose their draft record or answers. The active assessment index prevents duplicate staff/year assessments.

## Verification

Read-only local SQL probes of the actual source queries returned 13 eligible staff and 13 submissions in 2026/27, no duplicate staff, and zero rows for an identity without visible staff. The process query returned 107 records. All 55 generic/CPD submitter values matched independently selected canonical submission actors; all 13 ELI values matched explicit submission audit actors. Across the process records, 51 historical/workflow rows had no recorded submitting actor and intentionally retained null. Local data in this year does not provide an eligible non-submitter example, so this probe alone does not exercise that branch.

Artifacts are under `.localappdata/reporting-baseline/`: `eli-roster-admin.sql/.txt`, `eli-roster-denied.sql/.txt`, `dashboard-submitter-parity.sql/.txt` and `eli-submitter-verification.json`. Each query completed in less than one second wall time. No fixture, configuration or data mutation was performed.

`tests/eli-submission-report-runtime.ps1` passed against the restarted API for both 2026/27 (13 submitted, zero not submitted) and 2025/26 (zero submitted, one not submitted). Named cohorts matched every ELI aggregate denominator/submitted count, there were no duplicate staff, non-submission metadata was null, invalid years returned no staff, and process records carried the nullable submitter field. Its PowerShell reader explicitly enumerates JSON arrays before counting/filtering.

The shared dashboard record table now includes **Submitted by** on each form dashboard and a separate **Staff member** column on person-based processes. Learning Walk and ALS Learning Walk no longer show the misleading Key measure column; genuine scores and activity totals elsewhere remain under Outcome / activity. Detail search includes the submitting person's name. ELI has an expanded submission breakdown with counts, All staff / Submitted / Not submitted selectors, search, pagination, staff-profile links and submitted-assessment links. It uses year and organisation scope, independently of record date/theme/status filters, with that distinction stated beside the list.

PDF exports expand the recorded submitter and the named ELI cohort. Dashboard Excel exports preserve existing form columns and add Submitted by, plus an ELI staff submissions sheet. Three export tests verify organisation/exclusion filtering, record identity rather than owner/subject inference, PDF content, and OpenXML validity without leaking draft record references.

Integrated verification: 394 backend tests passed (one opt-in database test skipped in the normal run); the three new export tests also passed separately after a nullable-test warning was corrected. All 41 existing frontend tests passed. The production web build passed. Browser checks confirmed ELI detail headers, single-staff search, faculty scope, a named non-submitter in 2025/26, and Learning Walk's actual submitter names with no Key measure heading. Academic year and organisation filters were restored afterward. No database migration, data change, GitHub write or deployment was performed.
