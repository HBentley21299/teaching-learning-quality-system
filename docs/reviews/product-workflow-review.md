# Workflow experience review — 29 October 2026

This review covers the staff-facing registers and workflow forms in `ModuleWorkspace`, `LivVisits`, `ProbationObservations`, `CoachingMentoring`, `ElevatePractice`, `UcoTlaReviews`, `ActionsView` and `WorkScrutinyCreateForm`. The application shell, preferences, administration, QA and shared visual system have separate owners in the same review. The existing working changes, assessment wording, authored question order, permissions and data were preserved.

## Integration notes and limits

Probation and LIV registers span academic years and have their own year filters. Their linked actions must therefore receive the full permitted action history. LIV now requests that history directly; probation's prop scope and the shell's misleading global year control were identified and handed to the shell owner. Per-year routes retain their own year scopes. No action permission was widened.

Server validation remains authoritative. Form-specific frontend links cover the existing locally validated requirements; server conflicts and other authoritative rejections continue to appear as feedback while preserving entered work. This review does not claim that every possible server rejection has a field-level error code when the API only returns a message. Browser-specific screen reader behaviour and production account combinations still require the parent review's wider verification.

## ELI loading follow-up

The seven assigned workflow files now use the shared `LoadingState` for genuine pending requests. ELI assessment entry and UCO access checks use page presentation; registers, form templates and result retrieval use section presentation; action-owner and delivery-area lookups use inline presentation. Opening a UCO review or coaching session and changing a coaching cycle each have a contextual label. The shared component owns the decorative animation, live-region semantics and reduced-motion behaviour.

LIV, probation and UCO previously repeated the same loading message above and inside their registers. Each now announces that request once. Previously loaded register rows remain visible during refresh, while initial loading suppresses misleading empty results. Work Scrutiny announces its sub-team form once instead of separately announcing the same template's course levels. Failed requests stop the loader and retain their error/retry presentation. A failed generic form definition shows its existing error instead of continuing to claim that fields are loading.

No artificial delays, simulated progress or changes to save/completion timing were added. Additional real-handler tests cover LIV's single pending-to-error transition, UCO register retention during a failed review open, and ELI population retention during and after a failed refresh.
