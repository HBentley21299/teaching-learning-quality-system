# ELI loading integration — reporting, QA and administration

The shared `LoadingState` now replaces bare pending-state text in Dashboard, UCO reporting, saved form-data registers, QA Hub/review/evidence screens and the existing administrator fetch surfaces. Its illustration, animation, reduced-motion handling and visual styling are owned by the shared component/style pass.

Reporting has one loading announcement per pending dataset. The Dashboard header badge stays visible without a second live region while the main request is pending. The form-data explorer retains available identity summaries and uses a single illustrated loader; it does not announce zero results or an empty register before the request finishes. Column and expanded-record notes no longer create additional live loading announcements. Errors retain their messages and retry actions, with the illustration removed.

Administrator integration covers active AdminCentre subpanels, CSV import setup, room and managed-list catalogues, staff details, record/audit views, Work Scrutiny and Elevate Practice corrections, permissions, organisation structure, faculty settings, badge assets, form templates, messaging sources/version history and QA question/access/outcome settings. `CollapsibleSection` supplies the same loader when its expanded section is actually fetching, including delivery history and profile lists; its toolbar remains available across loading/error/empty states. Permissions distinguishes source loading from general busy/save state.

No loader was added to `EliSubmissionBreakdown`, because it receives ready arrays from the parent Dashboard's dataset gate. `QaDashboardDataExplorer` delegates its request to the integrated explorer. `QaAdminCentre` and legacy `FormEditor` delegate fetching to their focused panels. Native select placeholder text and busy action-button labels remain concise controls rather than separate graphic loaders. Optional sources were not forced to load.

The existing data selection, request cancellation, access checks, export filters, CSV confirmation and save behavior remain in place. No data, database, API contract or loading delay was introduced. No requests were artificially slowed in the application.

Validation uses the real shared loading component in the deterministic component harnesses. New deferred-request cases check Dashboard export gating, one explorer announcement without false empty results, loader removal on UCO and QA errors, and retained recovery. The final targeted run passed 115 tests across administration, CSV, shared usability, data explorer, dashboard switching, UCO and profile/team harnesses. TypeScript project build passed. Native animation and narrow-screen visual checks are handled by the root reviewer and are not claimed by these handler tests.
